# 프론트엔드 담당 AI 작업 지시서

## 담당 목표

사용자가 파도길의 핵심 흐름을 끊김 없이 경험할 수 있도록 화면을 구현합니다.

핵심 흐름:

권역 선택 -> 4단계 설문 -> 추천 코스 결과 -> 코스 상세 -> 해시태그 탐색

## 우선 작업

1. 권역 선택 화면 구현
2. 설문 화면 구현
3. 추천 코스 카드 UI 구현
4. 코스 상세 UI 구현
5. 해시태그 탐색 UI 구현

## 주로 수정할 파일

```txt
app/page.tsx
app/survey/page.tsx
app/courses/page.tsx
app/explore/page.tsx
app/globals.css
components/survey/
components/course/
types/survey.ts
types/course.ts
```

## 건드리지 않을 파일

```txt
lib/tourapi/
lib/supabase/
app/api/
```

백엔드/API 담당과 충돌을 줄이기 위해 API 라우트는 직접 수정하지 않습니다.

## 화면별 요구사항

### 권역 선택

- 강릉, 고성/속초, 양양, 동해, 삼척을 카드로 표시합니다.
- 각 카드에는 대표 키워드를 보여줍니다.
- 선택하면 설문 화면으로 이동합니다.

### 설문

- 단계는 4개입니다.
- 동반 인원, 이동수단, 반려동물, 연령대를 선택합니다.
- 사용자가 현재 몇 단계인지 알 수 있어야 합니다.
- 마지막 단계 이후 추천 결과 페이지로 이동합니다.

### 추천 결과

- 코스 2~3개를 카드로 보여줍니다.
- 각 카드에는 제목, 요약, 해시태그, 주요 장소 요약이 들어갑니다.
- 코스 상세로 이동하는 버튼이 있어야 합니다.

### 코스 상세

- 장소를 순서대로 보여줍니다.
- 각 장소의 이름, 카테고리, 주소, 태그를 보여줍니다.
- 지도 영역은 백엔드/지도 담당이 붙이기 전까지 placeholder로 둬도 됩니다.

### 해시태그 탐색

- 선택한 태그와 관련된 장소 리스트를 보여줍니다.
- 관광지, 음식점, 숙박, 레포츠 필터 UI를 준비합니다.

## 완료 기준

- 모바일과 데스크톱에서 화면이 깨지지 않습니다.
- 설문 흐름이 끝까지 이어집니다.
- 더미 데이터만으로도 발표 시연이 가능합니다.
- API 연결 전이어도 UI 구조가 유지됩니다.
