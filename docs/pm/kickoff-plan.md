# 첫 회의 PM 플랜

회의일: 이번 주 목요일
팀 규모: 4명
협업 방식: GitHub 이슈/브랜치/PR 기반
PM 역할: 일정, 범위, 사용자 흐름, API 연동 우선순위, 회의 액션 아이템 관리

## 회의 목표

1. 파도길의 MVP를 한 문장으로 합의한다.
2. 개발해야 할 화면과 API를 확정한다.
3. 4명 역할을 나누고 첫 주 작업을 GitHub 이슈로 배정한다.
4. 관광공사 OpenAPI 사용 범위를 확정한다.
5. 목요일 회의 이후 바로 개발 가능한 상태를 만든다.

## 내가 PM으로 할 일

- 기획서 기반 사용자 흐름 정리
- MVP 범위 확정안 작성
- Next.js + Supabase 기준 파일 구조 설계
- 관광공사 OpenAPI 연동 대상 정리
- GitHub 이슈 백로그 초안 작성
- 회의 안건과 결정사항 템플릿 작성
- 개발 우선순위 조율
- Vercel 배포 체크리스트 관리

## 추천 역할 분담

### 1. PM/서비스 구조 담당

담당: PM

- 사용자 흐름, MVP 범위, 일정 관리
- GitHub 이슈 관리
- API 요구사항 정리
- 회의록과 결정사항 관리

### 2. 프론트엔드 담당

- 권역 선택 화면
- 설문 화면
- 추천 코스 카드 UI
- 해시태그 탐색 UI
- 반응형 레이아웃

### 3. 백엔드/API 담당

- 관광공사 OpenAPI 연동
- 추천 코스 생성 API
- Supabase 데이터 모델
- API 캐싱과 에러 처리

### 4. 지도/데이터 품질 담당

- 카카오 지도 연동
- 장소 좌표/동선 표시
- 펫프렌들리 필터 검증
- 샘플 코스 데이터 검수

## 목요일 회의 안건

1. 서비스 한 줄 정의 확인
   - "강원 동해안 권역과 여행 조건을 선택하면, 관광공사 데이터를 기반으로 2~3개 맞춤 코스를 추천하는 웹 서비스"

2. MVP 화면 확정
   - 홈/권역 선택
   - 4단계 설문
   - 추천 코스 결과
   - 코스 상세
   - 해시태그 탐색

3. MVP 데이터 확정
   - 국문관광정보 서비스
   - 관광지별 연관 관광지 정보 서비스
   - 반려동물 동반여행 서비스

4. 추천 로직 1차 버전 합의
   - 권역 + 동반 인원 + 이동수단 + 반려동물 + 연령대 기준
   - 2~3개 코스 생성
   - 코스별 관광지, 음식점, 숙박, 레포츠 후보 조합

5. GitHub 운영 규칙
   - `main`: 배포 가능 상태
   - `develop`: 통합 개발
   - `feature/*`: 기능별 작업
   - 모든 작업은 이슈 생성 후 PR로 병합

6. 이번 주 액션 아이템 배정

- 로그인/찜 기능을 MVP에 포함할지

- 발표/시연용 샘플 권역을 어디로 잡을지
